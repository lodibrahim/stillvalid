# Decisions

Newest first. Each entry: decision · why · alternatives considered.

| Date | Decision | Why | Alternatives |
|---|---|---|---|
| 2026-09-27 | Issue → `likely_fixed` from references: same-repo PR merged into the scanned branch after the issue was filed (`high` if it says it fixes the issue, else `medium`), or a referencing commit on the branch (`medium`); skipped if the issue was reopened after the merge/reference. Every qualifying PR/commit is evidence; logic lives in the pure `check` module (`src/check/issues.rs`; `check/mod.rs` holds shared types so other checks can add sibling files) | First real verdict, from data already fetched; evidence is the PR/commit itself | Require `fixes #N` only (misses plain mentions); count PRs merged into any branch |
| 2026-09-27 | A commit is "on the branch" when REST `compare/{head_sha}...{oid}` (`per_page=1`, only `status` read) is `behind` or `identical` (the scanned `head_sha`, not the branch name, so a push mid-scan can't disagree with the report and odd branch names need no URL-encoding); 404/422 mean not on branch; other errors fail the scan. One call per unique referenced oid | Works without a clone and on Windows; unknown or unrelated commits are normal, rate limits are not | Clone and `git merge-base --is-ancestor` (clone not built yet); GraphQL `associatedPullRequests` (misses direct pushes) |
| 2026-09-27 | A commit referenced several times uses its **latest** reference time against reopens; latest `ReopenedEvent` per issue is kept | A re-push that mentions the issue after a reopen is a new signal | Earliest reference time |
| 2026-09-27 | A commit that is also a qualifying PR's merge commit is **kept as separate evidence** (no dedup) | Simple; both are true and point at the same change | Map commits to PRs and drop duplicates (extra API calls) |
| 2026-09-27 | Reopen events share the **100-events-per-issue** timeline cap; a reopen past the cap is missed | Same query, no extra requests; very long timelines are rare | Paginate timelines per issue |
| 2026-09-27 | Local repo via the **system `git`** (require **2.38+**, checked once per scan with a clear error), not `git2`/`gix` | libgit2 has no partial clone or `merge-tree --write-tree`, which later PR checks need; no C build, no new license; Git for Windows has every feature used | `git2` (vendored libgit2 + OpenSSL on Linux); `gix` (large tree, merge-tree incomplete); require only 2.31 now |
| 2026-09-27 | Clone = **blobless partial clone of only the dev branch** (`--filter=blob:none --single-branch`), then detached checkout of `head_sha`; later runs `fetch` the branch into the same clone | Full history for per-file log and merge-tree, blobs at head fetched in one batch, old blobs only on demand; ripgrep: 7.8 MB, 0.9 s | Full clone (much larger); bare clone (every file read a lazy network fetch) |
| 2026-09-27 | Clone cache in the **OS cache dir** (`<cache>/stillvalid/repos/<owner>/<repo>`), resolved by hand from `XDG_CACHE_HOME`/`HOME`/`LOCALAPPDATA` | Survives between runs without cluttering the output dir; no new dependency | `dirs` crate; `.stillvalid/` next to `--out` |
| 2026-09-27 | If the branch moved between the API call and `git fetch`, still check out the API's `head_sha` when it exists locally; error only when it's gone (force-push) | Keeps the scan consistent with the fetched issues/PRs | Error on any mismatch |
| 2026-09-27 | `--repo-path <dir>` uses an existing checkout **untouched** (no fetch/checkout); it only has to contain `head_sha`. Later checks read files from git objects at `head_sha`, not the working tree | The Action already runs actions/checkout with `fetch-depth: 0`; never modify a user's checkout | Require `HEAD == head_sha` |
| 2026-09-27 | Token reaches git only via `GIT_CONFIG_COUNT/KEY/VALUE` env as `http.https://github.com/.extraheader` (Basic `x-access-token`, as actions/checkout), plus `GIT_TERMINAL_PROMPT=0`; adds the **`base64`** crate (already in the tree via octocrab) | Not in argv, `.git/config`, or the remote URL; sent to github.com only; private repos without a token fail fast | Token in the URL (lands in `.git/config`); credential helper script; hand-written base64 |
| 2026-09-27 | `scan` always resolves the local repo, in every mode, even though no check reads it yet | Every later heuristic needs it; failures surface now | Only with `--repo-path` |
| 2026-09-27 | Indexer: `index::extract(title, body)` returns `Path` / `Symbol` / `Error` / `Frame` references, deduplicated by kind + canonical text (`path` or `path:line`), ordered by first appearance; frames also emit their symbol and path; paths normalized to `/` without a leading `./` | One flat list is easy to match against the repo later; `path` and `path:line` stay separate so line-level evidence isn't lost | Nested frame structs; per-kind lists |
| 2026-09-27 | Add **`regex`** as a dependency (was already in the lockfile via wiremock) | Five stack-frame formats plus paths would be ~3x the code hand-written, and buggier | Hand-written parsers |
| 2026-09-27 | Stack frames in v0.1: **Rust, Python, JS/Node, Go, Java**; gdb, C#, Ruby, PHP skipped | Go and Java cost one pattern each; the rest are rare in target repos | Rust/Python/JS only |
| 2026-09-27 | Indexer noise filters: paths need a file extension (bare `name.ext` only for known code extensions); only `github.com/.../blob/` URLs yield paths (tree URLs are ambiguous with slashed branch names); toolchain/dependency paths (`/rustc/`, `library/std/`, `.cargo/registry`, `site-packages`, `node_modules`, `/usr/`, `/lib/python`, `node:`) and std/runtime frames dropped; backticked plain words aren't symbols; errors only from line starts, capped at 200 chars | Keeps references that could match the repo; ripgrep eval: 41/43 correct on 10 hand-checked issues | Keep everything and filter at match time; also scan tree URLs |
| 2026-09-27 | Blob URLs to **other repos** are still emitted | `extract` doesn't know the scanned repo; matching checks the file exists at `head_sha`. Same check catches blob URLs on slashed branches (`blob/feature/x/src/a.rs` parses as `x/src/a.rs`) | Pass the repo into `extract` |
| 2026-09-27 | Raise `rust-version` to **1.85** (supersedes keeping 1.80) | Lets Dependabot move to octocrab 0.54 and sha2 0.11; 1.85 is from Feb 2025, so few users are affected | Stay on 1.80 and ignore newer releases in Dependabot |
| 2026-09-27 | Issue references come from GraphQL `timelineItems` (cross-referenced, connected, referenced events); **same-repo only**; PRs deduplicated with `will_close` = "fixes #N" or sidebar link; first 100 events per issue, 50 issues per page | One query covers 50 issues (~60 requests for 3,000 issues vs one REST call each); other repos' PRs can't fix this repo's code | REST timeline per issue; `closedByPullRequestsReferences` (misses plain mentions and commits) |
| 2026-09-27 | Without a token, timelines are **skipped** with a warning instead of failing | GitHub's GraphQL API requires auth; `basic` mode must still run anywhere | Fail the scan |
| 2026-09-27 | References are held in memory, **not written to `report.json`** yet | They surface as `evidence` once the "referenced by merged PR" heuristic exists; no schema change needed | Add a `references` field now |
| 2026-09-27 | Supply-chain checks with **cargo-deny** (advisories, licenses, sources) in CI; GitHub Actions pinned to commit SHAs; CI token `contents: read`; Dependabot weekly | Enterprise-grade hygiene for an OSS tool that handles tokens; cargo-deny covers `cargo audit`'s RustSec checks too | cargo-audit only; tag-pinned actions |
| 2026-09-27 | Ignore **RUSTSEC-2023-0071** (`rsa` timing side channel) in `deny.toml` | No fixed `rsa` exists; octocrab requires a JWT backend, and stillvalid never signs with an RSA key. Revisit when octocrab/jsonwebtoken drop `rsa` | `jwt-aws-lc-rs` backend (needs C toolchain, harder Windows builds); replace octocrab (design change) |
| 2026-09-27 | Report fields: `tier: "none"` for unchecked items; `summary.pulls.cant_tell` added | Every item is `cant_tell` until checks exist, and "no evidence → `cant_tell`" applies to PRs too; both additive, so `schema_version` stays 1 | Label unchecked items `heuristic` (misleading); drop PR `cant_tell` count (summary wouldn't add up) |
| 2026-09-27 | Fetcher lists issues/PRs via **REST** (`/issues`, `/pulls`) with `Link` pagination; GraphQL deferred to timeline cross-references | REST gives PR `head.sha` directly and is simplest to paginate and test; roadmap item split in two | GraphQL for everything now (more code before any verdict exists) |
| 2026-09-27 | Minimal own serde structs + `octocrab::get`/`all_pages`, not octocrab's typed models | Typed models require dozens of fields, break on API drift, and make test fixtures huge | octocrab `issues().list()` / `pulls().list()` |
| 2026-09-27 | Crate is **lib + bin** (`src/lib.rs` holds modules, `main.rs` is the CLI) | Matches "thiserror in library modules"; lets public contract types exist before every variant is used | Binary-only with `#[allow(dead_code)]` |
| 2026-09-27 | Issue `body_hash` = sha256 of body only | Comments aren't fetched yet; will extend when they are (one-time re-check) | Include title |
| 2026-09-27 | `rust-version` 1.80 kept; cargo's MSRV-aware resolver picks octocrab 0.49, sha2 0.10 | Don't change the declared MSRV without asking | Bump to 1.85 for octocrab 0.54 |
| 2026-09-27 | License: **MIT OR Apache-2.0** | Rust ecosystem norm; maximizes adoption; Apache adds patent grant | MIT only, MPL-2.0, AGPL-3.0 (scares corporate adopters) |
| 2026-09-27 | Name: **stillvalid** | Says exactly what it checks; free on crates.io, npm, GitHub org, Homebrew | Issue Lens (clashes with microsoft/IssueLens), isitfixed (GitHub user taken), backsift, issuesift, stillopen |
| 2026-09-27 | Language: **Rust**, single native binaries via **cargo-dist** | Must install on macOS/Linux/Windows with no runtime; small binaries (~10 MB); mature release tooling | TypeScript/Node (needs Node), Bun/Deno compile (50–90 MB binaries) |
| 2026-09-27 | Ship **CLI + GitHub Action** from one codebase | CLI for trying/dev/any CI; Action for nightly adoption; Action wraps the CLI | GitHub App (easiest install, but needs a server and the author pays compute/AI) |
| 2026-09-27 | Results surface **inside GitHub** first (labels, pinned issue, Projects), Pages dashboard for depth | People see it where they already work | Separate website only |
| 2026-09-27 | Three **modes**: `basic`, `free-ai` (default), `pro-ai` | No key or cost needed to start; BYO key for accuracy/scale | API-key-only |
| 2026-09-27 | **No server**: state in `report.json` on `gh-pages` | Zero hosting; any repo adopts with one workflow file | SQLite + hosted service |
| 2026-09-27 | **Read-only by default**, never auto-close | Trust; maintainers decide | Auto-close likely-fixed |
| 2026-09-27 | **Verdict + evidence** as the core contract | Distinguishes from age-based stale bots and guessy AI triage | Scores without evidence |
